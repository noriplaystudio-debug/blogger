Google Blogger 글쓰기 에이전트 최종본 업데이트 방법

v12 업데이트 핵심
- 제목 후보 불일치 자동 보정
- AI JSON 형식 오류 자동 복구
- 검수 형식 실패 시 완성 초안 보존
- 공식 출처 URL 경로 차이 자동 연결
- 자동 보정 내역 화면 표시
- 검수 형식 오류 시 OpenAI 자동 대체 검수
- 검수 실패 초안 자동 펼침
- 근거 부족 시 다른 글 방향·다음 키워드 자동 대체
- NEEDS_REVIEW 글 수동 Blogger 임시저장

1. 기존 에이전트 명령창에서 Ctrl+C를 눌러 종료합니다.
2. 기존 폴더의 .env.local 파일을 별도 위치에 복사해 둡니다.
3. 이 ZIP을 새 폴더에 압축 해제합니다.
4. 보관한 .env.local 파일을 새 폴더 최상위에 복사합니다.
5. 새 폴더 주소창에 cmd를 입력해 명령 프롬프트를 엽니다.
6. 아래 명령을 한 줄씩 실행합니다.

npm install
npm run check
npm run dev

7. 브라우저에서 http://localhost:3000 을 엽니다.
8. 상단이 'Google Blogger 연결됨'인지 확인하고 '통계 새로고침'을 누릅니다.
9. 첫 글을 만들기 전에 '전체 점검 실행'을 누르고 '첫 글 작성 전 필수 연결이 모두 정상입니다.' 문구를 확인합니다.

참고
- Windows 로컬 계획·검색 결과는 기본적으로 %LOCALAPPDATA%\BloggerWritingAgent에 저장되므로 새 폴더로 업데이트해도 유지됩니다.
- .env.local에는 API 키와 Google OAuth 설정이 있으므로 다른 사람에게 보내거나 ZIP에 포함하지 마세요.
- 연결이 만료되었다고 표시될 때만 Google Blogger 연결 버튼을 다시 누르면 됩니다.
- 연결 후 `http://localhost:3000/api/blogs`를 열었을 때 JSON의 `blogs` 안에 만든 블로그가 보이면 목록 연결이 정상입니다. 오류가 나면 `code`와 `diagnostic`을 함께 보내 주세요. 토큰이나 API 키는 이 응답에 포함되지 않습니다.
- `npm run check`는 기능 요구사항, Blogger·OpenAI 요청 형식, 타입 검사와 프로덕션 빌드를 모두 확인합니다.
- 새 버전은 계획 단계에서 키워드별 독립 출처 후보를 확보하고, 작성 시 최대 3단계 보강 검색을 진행합니다. 끝내 근거가 부족한 글만 '출처 보강 필요'로 격리되며 나머지 대기열은 계속 처리됩니다.
- 이전 버전에서 WORKING에 멈춘 로컬 작업은 새 버전을 열면 재시도 가능한 오류 상태로 자동 복구됩니다.
- 새 주간 계획부터 카테고리의 약 40%(최소 1개)를 검증 가능한 사건·연예·스포츠 등 실시간 관심 트랙으로 우선 검토합니다. 기존에 저장된 계획은 그대로 유지되므로 이 기준을 적용하려면 '새로 웹 조사해 계획 만들기'를 한 번 실행하세요.
- 실시간 글의 현재성 유효시간이 지나면 공개가 차단됩니다. 제작 대기열의 '실시간 정보 다시 확인·재작성'을 누른 뒤 기존 Blogger 임시글에 수정본을 반영하고 공개하세요.
- 새 계획 생성은 카테고리, 카테고리별 키워드, 키워드별 글 방향으로 나눠 실행하고 단계마다 자동 저장합니다. 중간에 시간 초과가 나면 같은 버튼의 이름이 '저장된 지점부터 계획 계속 만들기'로 바뀝니다. 이 버튼을 다시 누르면 완료 구간의 API 검색 비용을 반복하지 않고 실패 지점부터 계속합니다.
- 진행 중에는 기존 완성 계획과 제작 대기열을 유지하며, 새 계획의 최종 검증과 저장이 모두 성공한 뒤에만 교체합니다. 컴퓨터를 껐다 켜도 같은 프로젝트를 실행하면 저장된 진행 지점이 복원됩니다.
- `글 방향이 정확히 N개가 아닙니다` 오류를 수정했습니다. 모델이 요청 수보다 많이 만들면 설정 수만 사용하고, 적게 만들거나 필수 브리프를 빠뜨리면 부족분을 자동 보충합니다. 업데이트 후 기존 진행 계획을 폐기하지 말고 `저장된 지점부터 계획 계속 만들기`를 누르면 됩니다.
- 저장된 `planningRun`이 있는데도 버튼이 `새로 웹 조사해 계획 만들기`로 표시되던 설정 불일치를 수정했습니다. 진행 계획의 당시 수량 설정을 자동 복원하며, 앱 시작 시 기본값이 체크포인트를 덮어쓰지 않습니다.
- 여러 글을 한 번에 작성하는 동안 `새 작업 시작 일시정지`를 사용할 수 있습니다. 현재 글 하나가 끝나면 멈추며 완료 글과 남은 대기열은 저장됩니다. API 키·인증·결제·사용량 같은 공통 오류는 첫 실패에서 자동 중지됩니다. 설정을 수정한 다음 `오류 작업부터 이어서 N개 작성`을 누르면 실패 글부터 재개합니다.
