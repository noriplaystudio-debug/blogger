# seed 운영안 v5.2

작성일: 2026-10-20 · 상태: 운영 초안 및 테스트 구현

seed는 아이디어의 요약을 무료로 공개하고, 상세 열람권과 독점 사용권을 따로 판매하는 거래 플랫폼입니다.
플랫폼은 거래 금액의 일부를 수수료로 가져갑니다.
현재 결제·환불·정산은 실제 돈이 오가지 않는 테스트이며, 아래 기준은 운영자가 조정할 수 있는 초기안입니다.

## 1. 상품의 기준

추상적인 한 줄의 생각보다 실행에 필요한 기획과 자료를 상품화합니다.

| 구분 | 포함할 내용 | 가격 설정 방향 |
| --- | --- | --- |
| 아이디어 | 구체적인 문제, 대상 사용자, 해결 방법, 이미지, 첫 실행 계획 | 낮은 진입 가격 |
| 구체화 기획 | 사용자 흐름, 핵심 화면, 초기 비즈니스 모델, 검증 계획 | 자료의 깊이에 맞는 중간 가격 |
| 전문 기획 | 근거 자료, 실험 결과, 비용·일정 가정, 차별점과 한계 | 근거와 제공 범위에 맞는 높은 가격 |

기획 수준은 판매자의 분류입니다. 운영 검토를 통과했다고 사업성·특허 가능성·법적 독점권을 보증하지 않습니다.
전문가 인증 배지는 별도의 자격 및 검증 절차가 생기기 전에는 사용하지 않습니다.

분류는 아이디어 종류 → 세부 유형을 먼저 선택합니다. 제품·발명, 음악·사운드, 미술·디자인, 사업·창업 등 16종류와 117세부 유형을 제공합니다.
건강·의료, 환경·에너지 같은 관련 분야 16개는 별도로 최대 3개를 선택하며 기획 수준과 구분합니다.
등록 시 종류에 맞는 작성 질문을 안내하고, 탐색에서 종류·유형·관련 분야·수준·가격·판매 상태를 조합합니다.
[전체 카테고리와 분류 기준](CATEGORY_POLICY.md)에 포함·제외 범위와 중복 구분 예시를 정리했습니다.
기존 글의 원문·가격·거래 기록은 바꾸지 않고 새 분류 제안을 제공하며, 불명확하면 분류 확인 필요로 표시합니다.

권장 가격과 무료 나눔은 [v5.1 운영 기준](PRICING_AND_SHARING.md)을 따릅니다. 권장 상한은 안내이며 등록·구매 제한이나 수익·품질 보증이 아닙니다.

무료 나눔의 금액 의견은 [v5.2 수집·집계 기준](COMMUNITY_PRICE_OPINIONS.md)에 따라 보관한다. 실제 거래가와 구분하고, 익명 집계와 표본 조건을 운영자가 검토하며 가격 상한은 자동 변경하지 않는다.

## 2. 회원과 권한

| 주체 | 가능한 일 | 제한 |
| --- | --- | --- |
| 비회원 | 승인된 아이디어의 제목·요약·공개 커버·가격 확인 | 상세 자료와 비공개 이미지 접근 불가 |
| 판매자 | 기획·이미지 등록, 심사 결과 확인, 매출·정산 조회, 문의 답변 | 구매자 권한을 임의로 부여하거나 정산 완료 처리 불가 |
| 구매자 | 열람권 구매, 비사용 서약, 독점 사용권 추가 구매, 문의 접수 | 열람만으로 사용권 취득 불가 |
| 운영자 | 공개 검토, 게시 중단, 신고·분쟁 검토, 테스트 환불·정산, 수수료 정책 관리 | 관리자 ID는 서버 설정으로만 지정 |

판매자·구매자 역할은 첫 가입 시 하나를 선택하고 서버에 저장합니다.
로그인 제공자와 별개로 내부 회원 ID에 주문·권리·정산 기록을 연결합니다.
같은 이메일이라는 이유만으로 서로 다른 소셜 계정을 자동 합치지 않습니다.

## 3. 판매 등록과 공개 검토

판매자는 아래 항목을 작성합니다.

- 무료 공개: 제목, 요약, 카테고리, 기획 수준, 태그, 두 가지 가격, 선택한 공개 커버.
- 결제 후 공개: 문제 정의, 해결 방법, 대상 사용자, 실행 계획, 구체적 참고 이미지 1~5개.
- 검토 자료: 직접 창작한 근거와 출처, 검증한 내용과 미검증 부분, 실행의 한계와 위험.
- 판매 조건: 열람권·사용권 수수료, 정산 대기 기간, 판매 권한 및 정책 동의.

등록 → 검토 대기 → 공개 승인 또는 반려 → 판매 중 → 독점 사용권 구매 시 판매완료.
심각한 문제가 확인되면 운영자가 게시·상세 열람을 중단할 수 있습니다.

검토 중인 글과 공개 커버는 판매자·운영자 외에는 직접 URL로도 볼 수 없습니다.
반려 사유는 판매자가 자신의 화면에서 확인합니다.
결제 이력이 없는 검토 대기·반려 글은 기존 본문·분류·가격·이미지를 불러와 수정하고 재검토를 요청할 수 있습니다. 등록 버전과 해시를 갱신하며 최초 수수료 조건은 유지합니다. 공개·게시 중단·결제 이력·판매완료 글은 수정할 수 없습니다. 환불 후에도 과거 결제 이력이 있으면 수정하지 않습니다.
판매자 동시 수정과 운영 승인에 등록 버전을 검사하여, 이전 버전의 검토 결과로 새 자료가 승인되지 않게 합니다.
등록과 재검토는 요청 번호·내용 해시를 같은 트랜잭션에 기록합니다. 응답이 끊겨도 본인 요청 결과를 확인하고 중복 등록 없이 재시도할 수 있습니다.
보완본을 만들 때는 새 등록으로 제출합니다. 향후 개정본 기능은 기존 구매 버전과 분리해야 합니다.

## 4. 두 단계의 거래

### 4.1 상세 열람권

1. 요약·가격·제공 자료를 확인합니다.
2. 상세 열람이 사용권을 포함하지 않는다는 서약을 읽고 동의합니다.
3. 열람료를 결제합니다. 현재는 실제 청구 0원의 테스트입니다.
4. 서버에서 권한을 확인한 뒤 상세 텍스트와 참고 이미지를 제공합니다.

최초 상세·이미지 접근의 계정, 시각, 버전을 기록합니다. 권한이 없는 요청에는 자료와 접근 기록을 제공하지 않습니다.
열람 이력이 있다는 사실만으로 모든 환불을 자동 거절하지 않습니다.

### 4.2 독점 사용권

1. 열람권을 가진 구매자가 사용하기를 선택합니다.
2. 별도 독점 사용료와 권리 조건에 동의합니다. 열람료와 사용료는 별도이며 자동 차감하지 않습니다.
3. 사용권이 확정되면 판매완료가 되고 다른 구매자의 상세 재접근을 차단합니다.
4. 같은 아이디어의 독점 사용권은 한 명에게만 생기도록 거래를 묶습니다.

판매완료 후에는 이전에 열람료를 낸 구매자도 상세 재열람이 중단됩니다. 내 계정과 주문 기록에 현재 권한을 표시하고, 열람이 막힌 경우 거래 기록과 문의로 연결합니다. 주문·서약·환불 기록은 보존합니다.
이 조건을 열람권 구매 전에 안내합니다.
이미 기억하거나 저장한 정보를 기술적으로 회수할 수는 없으므로, 접속 차단과 계약상 의무를 구분합니다.

현재 구현은 데이터베이스에서 단일 승자를 정하는 테스트 거래입니다.
실제 PG 연결 시에는 사용권 예약, 결제 승인, 서명 검증 웹훅, 중복 이벤트 방지, 실패 취소·환불을 연결해야 합니다.
테스트 성공을 실제 자금 처리의 검증으로 간주하지 않습니다.

## 5. 수수료와 수익 모델

초기 테스트 설정은 열람권 10%, 독점 사용권 10%입니다. 운영 화면에서 0~50% 범위로 바꿀 수 있습니다.
변경된 정책은 새 등록 아이디어부터 적용합니다. 기존 판매글과 이미 발생한 주문에는 소급 적용하지 않습니다.

수수료 = 거래 금액 × 수수료율, 원 미만 내림.
판매자 예상액 = 거래 금액 − 플랫폼 수수료.
실제 PG 비용과 세금 차감 전의 금액입니다. 과세·세금계산서·PG 비용 부담 주체는 실제 운영 약관과 계약에서 확정합니다.

| 예시 | 구매 가격 | 수수료 10% | 판매자 예상액 |
| --- | ---: | ---: | ---: |
| 상세 열람 | 5,000원 | 500원 | 4,500원 |
| 독점 사용 | 100,000원 | 10,000원 | 90,000원 |
| 합계 | 105,000원 | 10,500원 | 94,500원 |

위 표는 수익 구조 설명용 예시이며 현재 실제 청구액은 0원입니다.
매출 보장이나 실제 거래 실적을 뜻하지 않습니다.

거래마다 원금·수수료율·플랫폼 수수료·판매자 예상액·정산 가능일을 저장합니다.
환불은 원래 거래를 지우지 않고 원금·수수료·판매자 금액의 반환 기록을 별도로 남깁니다.
운영 매출은 환불을 제외한 수수료를 기준으로 확인합니다.

초기에는 거래 수수료를 중심으로 운영합니다.
광고성 노출이나 유료 추천은 구매자의 상품 선택을 왜곡할 수 있어, 별도 상품으로 도입할 때 표시 기준부터 정합니다.

## 6. 판매자 정산

초기 테스트 대기 기간은 거래 후 7×24시간이며 새 등록 건에 대해 1~30일로 조정할 수 있습니다.

거래 발생 → 대기 → 분쟁 없는 정산 가능액 → 판매자 요청 → 운영 검토 → 테스트 완료.

- 진행 중인 신고·환불·분쟁이 관련된 아이디어의 정산은 보류합니다.
- 환불된 거래는 정산 대상에서 제외합니다.
- 요청 시 해당 거래를 한 요청에만 배정하여 동시·반복 요청으로 중복 정산되지 않도록 합니다.
- 요청 후 새 분쟁이 생기면 정산 완료 처리를 차단합니다.
- 진행 중 요청을 취소하면 아직 유효한 거래가 다시 정산 가능 여부를 평가받습니다.
- 실제 송금, 계좌 수집, 판매자 본인확인·세무 확인은 아직 연결하지 않았습니다.

이미 정산 요청에 포함된 주문은 해당 요청을 먼저 취소한 뒤 환불 검토를 진행합니다.
이미 정산 완료된 주문은 자동 환불로 처리하지 않고 별도의 조정 절차가 필요합니다.
실서비스에서는 PG의 판매자 정산 및 본인확인 지원 범위를 우선 확인합니다.

## 7. 신고·환불·분쟁

신고 대상은 출처·권리 문제, 공개 설명과 제공 자료의 불일치, 자료 제공 오류 등입니다.
요청자는 사유와 사실을 적고 환불·거래 분쟁에는 자신의 주문을 연결합니다.
다른 사람의 주문으로 문의를 만들거나 판매자가 다른 판매자의 문의에 답할 수 없습니다.

접수 → 검토 중 → 판매자 설명 확인 → 종결·반려 또는 테스트 환불.

동일 아이디어에 같은 유형의 진행 중 문의는 한 건만 허용하고, 계정별 진행 중 문의 수를 제한합니다.
운영자는 최초 상세·이미지 접근 기록과 서약, 등록 버전, 판매자 답변을 함께 봅니다.
처리 사유와 계정·시각을 변경 이력에 남깁니다.

운영 목표 초안:

- 영업일 기준 1일 이내 접수 확인, 2일 이내 최초 검토.
- 추가 확인이 필요하면 진행 상태와 필요한 설명을 안내.
- 권리 침해가 의심되는 글은 노출·상세 접근의 중단 필요성을 우선 검토.
- 반복적인 허위 신고나 판매자 사칭은 별도의 제재 기준을 마련.

이 목표는 인력과 지원 체계를 확정한 뒤 공개 약관·고객 안내에 반영합니다.
현재 화면에 확정된 처리 기한으로 약속하지는 않습니다.

독점 사용권 환불 시 접근 권한은 중단하지만 자동으로 다시 판매하지 않습니다.
이미 제공된 자료, 권리 반환과 외부 이용 여부를 확인하는 별도 절차가 필요하기 때문입니다.
현재 버전에는 권리 반환 후 자동 재판매 기능을 두지 않았습니다.

## 8. 권리와 증빙

서약은 문구 전문, 버전, 동의한 계정과 서버 시각을 주문에 연결하여 저장합니다.
등록 기획과 이미지 식별자에는 내용 해시와 버전을 기록합니다.
상세·이미지 최초 접근도 자료 버전과 함께 기록합니다.

이 기록은 서비스 내부의 사실관계 확인에 쓰이며 외부 공증이나 법적 독점권을 만들어 주지 않습니다.
추상적인 아이디어 자체의 법적 보호 여부와 구체적 문서·이미지·코드의 권리를 구분해야 합니다.
사용권의 대상, 독점 범위, 기간, 지역, 재판매·재허락, 비밀유지, 반환 조건은 출시 전 계약으로 구체화합니다.
무단 사용이 곧바로 범죄나 승소로 이어진다고 홍보하지 않습니다.

## 9. 개인정보와 접근

- 활동에 필요한 계정·역할·연락용 기본 프로필과 거래 기록을 중심으로 저장합니다.
- 주민번호나 계좌를 자체 가입 양식에서 받지 않습니다.
- 키와 비밀값은 서버 환경설정에 두며 운영 화면에는 설정 여부만 표시합니다.
- 상세 자료와 비공개 이미지는 서버에서 매번 권한을 확인하고 공유 캐시를 사용하지 않습니다.
- 미완성 업로드는 수량·형식·용량을 제한하고 정상 취소 시 정리합니다.
- 계정별 권한과 운영자 ID를 브라우저의 역할 표시로 판단하지 않습니다.

실서비스 전 보강 항목은 보관 기간·삭제 요청·정기 백업·복원 점검·장기 미사용 업로드 정리입니다.
법정 거래 기록 보관과 일반 회원 탈퇴·삭제를 구분하는 정책도 필요합니다.

## 10. 운영 화면과 지표

현재 구현:

- 판매자: 등록글의 심사 상태, 거래별 수수료, 정산 대기일·가능액·요청 내역, 문의 답변.
- 구매자: 찜, 열람한 아이디어, 독점 사용권, 주문·서약 기록, 문의 접수와 처리 결과.
- 운영자: 공개 검토, 신고·분쟁·테스트 환불, 테스트 정산, 새 등록 수수료 정책, 로그인 설정 상태, 변경 이력.
- 운영 지표: 테스트 거래액, 환불액, 환불 제외 수수료, 검토 대기 건.

다음 단계의 지표:

유효 등록 수, 검토 통과율, 요약→열람 전환율, 열람→사용권 전환율, 실제 환불률,
신고 처리 시간, 판매 소요 시간, 반복 구매율과 실제 PG 비용을 반영한 순수익.
아직 수집·검증하지 않은 지표를 숫자로 만들어 화면에 표시하지 않습니다.

## 11. 로그인 연결과 출시 순서

소셜 앱 등록과 인증키 설정은 AUTH_SETUP.md를 따릅니다.
현재 Sites 배포는 플랫폼의 ChatGPT 인증을 유지합니다.
네이버·카카오·구글 및 선택적 이메일 인증은 독립 Node 인증 모드에 준비했습니다.

1. 최종 도메인과 배포 구성을 정하고 각 소셜 앱을 등록합니다.
2. 콜백 URL·동의 항목·키를 설정하고 실제 가입·로그인·로그아웃을 검증합니다.
3. 판매자와 구매자 역할, 자료 차단, 동시 사용권 구매, 환불·정산 시나리오를 브라우저에서 점검합니다.
4. PG 계약과 실제 결제·웹훅·취소·정산을 연결합니다.
5. 사용권·환불·개인정보·수수료 정책을 법률·세무 검토 후 확정합니다.
6. 백업·복원·운영 알림·지원 체계를 마련하고 소수 판매자로 운영을 시작합니다.

현재는 실제 소셜 계정 승인, 실제 PG 처리, 브라우저 전체 흐름, 배포 완료를 검증한 상태가 아닙니다.
서버·권한·금액·동시 요청·분쟁 상태 테스트와 소스 검사는 통과했습니다.


## v5 이용 흐름 보완

가입 후 구매·찜·등록 작업을 이어가며, 세션의 작업 식별자는 30분간 유효합니다. 재시도 번호는 계정·작업별로 최대 24시간 세션에 유지하고 성공 확인 후 제거합니다. 이 기록에 상세 본문·이미지·서약 동의는 넣지 않습니다. 실제 OAuth 왕복·브라우저 검증은 별도로 필요합니다.

판매자 계정에서 미사용 업로드를 조회·삭제할 수 있습니다. 등록에 쓰인 이미지는 삭제할 수 없고 삭제와 등록이 겹쳐도 DB 상태를 확인한 후 저장소를 정리합니다. 저장소 삭제 실패는 작업 기록을 유지해 이후 조회·업로드에서 재시도합니다. 자동 보관 기간과 정기 삭제는 아직 설정하지 않았습니다.

자세한 재현 순서와 확인 범위는 [판매자·구매자 흐름 점검](JOURNEY_REVIEW_V5.md)에 있습니다.
