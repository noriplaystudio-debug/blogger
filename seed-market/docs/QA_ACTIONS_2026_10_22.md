4. 운영 반려·판매자 기존 이미지 수정·재검토·승인: 통과.
5. 구매자 검색·무료 요약·새 가입 후 구매 복귀: 통과.

## QA-RUNNER-001: 거래 기록 버튼의 중복 선택

- 재현: 독점 판매 뒤 구매자 B의 보관함에서 `[data-action="receipt"][data-id="주문 ID"]`를 클릭한다.
- 실제: 같은 주문의 그림 버튼과 `권한 · 거래 확인` 버튼 두 개가 선택되어 strict mode 오류.
- 원인 근거: result.json, failure.html, failure.png, buyer-b trace에서 두 버튼을 확인했다. 제품의 JavaScript 예외는 `pageErrors: []`였다.
- 수정: 계정 패널 안에서 주문 ID와 `권한 · 거래 확인` 또는 결제 내역의 `권한 · 결제 기록` 버튼 이름을 함께 지정하고, 대상이 1개인지 확인한 뒤 클릭한다. 임의의 첫 번째 요소를 선택해 오류를 숨기지 않는다.
- 수정 범위: tests/browser.test.mjs. 실제 서비스 거래 동작은 이 러너 오류의 수정 대상이 아니다.
- 통과 조건: 다른 열람자의 권한 회수·거래 기록·문의가 완료되고 환불 확인 화면에서도 해당 주문이 정확하게 선택되어야 한다. 이후 전체 17단계 결과를 확인한다.

이 실행의 체크아웃은 bootstrap이 만든 소스 커밋이었다. 후속 검사는 일반 CI 워크플로로 전환해 QA 브랜치의 수정 커밋을 직접 checkout해야 한다. 이전 embedded source를 매번 복원하면 수정한 검사를 덮어쓰므로 같은 복원 워크플로를 후속 검사로 계속 사용하지 않는다.

## 수정 뒤 확인 상태

로컬 `npm run check`, `npm test`, `npm run qa:tools-test`는 통과했다. GitHub 브라우저 재실행 결과가 확인되기 전에는 이 수정의 UI 통과를 주장하지 않는다. 사이트 배포·OAuth·실제 결제·실제 휴대폰은 별도 검증 범위다.
