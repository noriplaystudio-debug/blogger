# seed v4 — 아이디어 종류별 분류 기준

첫 질문은 ‘어느 산업에 쓰는가’가 아니라 **‘어떤 아이디어를 거래하는가’**입니다.
판매자는 중심 결과물에 맞는 종류 하나와 그 안의 세부 유형 하나를 선택합니다.
관련 분야는 최대 3개를 덧붙이고, 기획 수준은 별도로 고릅니다.

## 세 가지 축

| 축 | 판단할 내용 | 예시 |
| --- | --- | --- |
| 아이디어 종류 → 세부 유형 | 구매자가 받게 될 구상 자체 | 제품·발명 → 스포츠·레저용품 |
| 관련 분야 | 어디에 활용하는 구상인가 | 건강·의료, 생활·가족 |
| 기획 수준 | 얼마나 구체화했는가 | 아이디어, 구체화 기획, 전문 기획 |

음악도 사업과 동일한 깊이의 대분류입니다. ‘전문 기획’이나 ‘AI’라는 말만으로 모든 창작물을 한곳에 묶지 않습니다.
예체능을 한 카테고리에 넣지 않고 음악, 미술·디자인, 영상, 글, 게임, 공연, 스포츠를 각각 찾게 합니다.

## 중심 결과물로 구분하기

| 구상 | 우선 선택할 종류 | 구분 이유 |
| --- | --- | --- |
| 새로운 운동기구의 구조 | 제품·발명 → 스포츠·레저용품 | 물리적 제품의 기능과 구조가 중심 |
| 초보자를 위한 운동 루틴 | 스포츠·운동·레저 → 운동 프로그램·트레이닝 | 움직임과 진행 방법이 중심 |
| 체육시설의 매출·가격 체계 | 사업·창업 → 수익·가격 모델 | 수익과 운영 구조가 중심 |
| 곡의 멜로디나 가사 | 음악·사운드 → 작곡 또는 가사 | 음악 창작 자체가 중심 |
| 콘서트의 무대·관객 동선 | 공연·무용·무대 → 콘서트·라이브 연출 | 무대와 관객 경험이 중심 |
| 음악을 가르치는 수업 구성 | 교육·학습 → 수업·커리큘럼 | 학습 목표와 수업 순서가 중심 |
| 새 악기의 작동 구조 | 제품·발명 | 악기를 만드는 구조가 중심 |
| 작곡을 돕는 앱의 기능 | 소프트웨어·AI | 프로그램의 동작이 중심 |
| 의자의 접힘 구조 | 제품·발명 → 생활·주방·가구 | 물건의 구조가 중심 |
| 의자 표면의 시각 패턴 | 미술·디자인·공예 | 시각 표현이 중심 |
| 매장 안의 가구 배치 | 공간·건축·도시 | 공간과 동선이 중심 |
| 게임 규칙과 플레이 내러티브 | 게임·인터랙티브 | 상호작용과 플레이가 중심 |
| 독립적으로 읽는 세계관·소설 | 글·스토리·출판 | 이야기 자체가 중심 |
| 새로운 소재의 비교 실험 | 연구·기술 원리 | 원리와 검증 방법이 중심 |

앱·서비스·사업이 결합된 구상은 판매할 자료의 중심을 고릅니다.
화면·기능·작동 방식은 소프트웨어, 제공 절차와 고객 경험은 서비스, 수익·운영 모델은 사업으로 구분합니다.
특정 종목의 코칭·운동법은 스포츠로, 일반적인 학습법·교재·수업 설계는 교육으로 분류합니다.

여러 요소가 있어도 중심 결과물이 명확하면 해당 종류를 선택합니다.
동등하게 중요한 요소를 하나로 묶은 복합 구상은 ‘복합·기타 → 융합·복합 기획’을 사용합니다.
분류나 제목만 바꾼 중복 등록은 같은 구체적 기획에 대한 판매 권한 문제를 해결하지 않습니다.

## 검색과 판매 등록

- 홈에서 네 묶음으로 정리한 전체 종류를 볼 수 있습니다. 묶음은 탐색을 돕는 메뉴이며 판매 분류 자체는 종류·세부 유형입니다.
- 종류를 고르면 그 종류의 세부 유형만 고를 수 있습니다.
- 관련 분야는 서로 다른 종류를 가로질러 찾습니다. 예를 들어 건강 분야에서 제품·앱·운동 프로그램을 함께 볼 수 있습니다.
- 종류·유형·분야·기획 수준·가격·판매 상태를 조합해 검색합니다.
- 종류 변경 시 기존 상세 글이나 입력 가격을 덮어쓰지 않습니다. 질문과 작성 예시만 바꿉니다.
- 음악에는 기획 의도·곡 구성·청취 대상·제작 계획, 제품에는 개발 배경·구조·사용 환경·시제품 검증 등을 안내합니다.
- 현재 첨부는 PNG·JPG·WebP 이미지입니다. 음악·영상 종류를 선택했다고 음원·영상 파일 첨부나 실제 권리 이전이 추가되지는 않습니다.

신규 등록은 서버에서도 종류와 세부 유형의 부모·자식 관계, 관련 분야 식별자와 최대 3개 제한을 검사합니다.
확정한 종류·유형·분야와 분류 버전은 등록과 같은 데이터베이스 작업으로 저장합니다.
사용권·가격·심사·정산 정책은 기존 거래 흐름을 따릅니다.

## 기존 데이터와 작성본

이전 ‘테크·AI / 라이프스타일 / 비즈니스 / 콘텐츠·디자인 / 소셜·커뮤니티’ 값은 원본에 남깁니다.
명확한 세부 분류는 새 유형에 연결하고, 그 밖의 글은 공개 제목·요약·태그의 단서로 분류를 제안합니다.
비공개 본문은 분류나 검색에 사용하지 않습니다.

단서가 없거나 여러 종류의 근거가 비슷하면 복합·기타에 두고 ‘기존 글 · 분류 확인 필요’로 표시합니다.
제안 분류는 판매자가 새로 확정한 분류처럼 표시하지 않습니다.
기존 원문·이미지·등록 해시·가격·주문·열람권·사용권·수수료 원장을 다시 쓰지 않습니다.
구형 카테고리와 세부 주제 URL은 이전 분류를 나타내는 조건으로 연결합니다.

v3 기기 작성본은 글과 가격을 보존해 불러옵니다. 새 분류를 다시 고르도록 안내하고 동의를 자동 복원하지 않습니다.
새 작성본에는 관련 분야도 저장하며 이미지와 동의 기록은 포함하지 않습니다.

## 구현과 검증 범위

분류의 기준 데이터는 `public/assets/taxonomy.js` 하나이며 API, 검색, 홈, 비교, 판매 작업실과 샘플이 함께 사용합니다.
새 `idea_classification` 테이블은 기존 카테고리·원문을 변경하지 않고 신규 등록의 확정 분류를 저장합니다.
배포 전 Drizzle 마이그레이션 생성·적용이 필요합니다. 로컬 실행은 시작 시 준비된 SQL로 테이블을 만듭니다.

16가지 종류의 API 등록, 세부 유형 오류·분야 제한, 교차 검색, 기존 유료 열람과 주문 보존,
구형 URL과 작성본 호환, 분류가 모호한 글의 표시를 테스트합니다.
로컬 창작 샘플은 21개이며 모든 종류를 포함합니다. 기존 샘플이나 사용자 글을 덮어쓰지 않습니다.
샘플의 사업성·운동 효과·연구 결과가 검증됐다고 표시하지 않습니다.

정적 HTML 미리보기는 디자인과 분류 선택·질문 구성을 확인하는 용도입니다.
실제 브라우저 전체 조작·OAuth·결제·배포 완료를 검증한 결과는 아닙니다.
