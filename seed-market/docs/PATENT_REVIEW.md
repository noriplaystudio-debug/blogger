# 판매 등록의 특허·권리 자료 검토 · v5.3.0

판매자의 신고, 운영자의 자료 대조, 전문가의 법률 판단을 구분합니다. 현재 구현은 신고와 수동 운영 검토입니다. 검색 결과가 없다는 이유로 특허가 없거나 비침해라고 판정하지 않으며, 자료 기록을 특허 인증으로 표시하지 않습니다.

## 실제 등록·검토·구매 흐름

1. 판매 작업실의 상세 자료 단계에서 미출원/출원 중/등록 신고/확인 필요/비대상, 국가·출원 경로, 권리관계, 직무발명·공동 권리·허락 근거, 검토할 구성, 선행기술 검색 현황을 받습니다. 음악·미술 등은 비대상 사유와 다른 권리의 확인 필요성을 기록할 수 있습니다. 한 건의 대표 번호를 받고 추가 참고자료는 검색 설명에 기재합니다.
2. 출원·등록 신고에는 번호와 출원인·권리자가 필요합니다. 번호 형식 검사만 수행하며 진위·존속·권리자를 자동 확인하지 않습니다. PCT는 국제출원 경로이며 전 세계에 유효한 특허권을 뜻하지 않습니다.
3. 공개 요약과 커버도 출원 전 공개에 영향을 줄 수 있음을 알리고 최종 단계에서 별도 확인을 받습니다. 임시저장·수정 복원 시 동의는 다시 체크해야 합니다.
4. 운영자는 **권리자·거래 권한 / 특허 등록 가능성 / 타인 특허 침해**를 나눠 기록합니다. 출원·등록 신고는 공식 자료 주소·확인일과 권한 근거 대조가 필요합니다. 허락받은 권리나 공동 권리도 근거 대조가 필요합니다. 기록에는 확인한 근거와 판단하지 않은 범위를 적습니다. 불명확한 권한, 보완 필요, 전문가 검토 필요 상태로는 공개 승인할 수 없습니다.
5. 자료 대조가 완료돼도 등록 가능성과 비침해는 미판단으로 표시합니다. 실제 신규성·진보성, 청구범위, 국가별 존속상태, 실시 위험 등에 대한 판단은 변리사 등 전문가 검토가 필요합니다. 현재 앱에는 전문가 인증·수임·결제·보고서 발급 기능이 없습니다.
6. 구매 전 상세/결제 화면에는 판매자 신고와 기록 범위를 안내합니다. 권리자·권한 설명·검토 메모는 판매자와 운영자에게만 보이고 유료 열람자에게도 제공하지 않습니다. 번호와 운영자가 기록한 공식 주소는 판매자가 공개를 선택한 경우에만 표시합니다.
7. 구매 화면에서 확인한 안내 버전을 서버가 검사하고 주문에 당시 공개 안내를 고정 저장합니다. 이후 신고/심사 변경으로 과거 주문 안내를 덮어쓰지 않습니다. 기존 글은 `특허 정보 미제공`, 과거 주문에 당시 기록이 없으면 기록 없음으로 표시합니다.

아이디어 자료의 독점 사용 조건과 특허권은 별개입니다. 구매로 특허권 양도·실시허락이나 제삼자의 특허 사용 허락이 자동으로 생기지 않습니다. `특허권 제외` 또는 `별도 계약·절차 협의`만 선택할 수 있습니다. 양도·실시허락의 실제 계약, 필요한 등록 및 법률 검토는 별도입니다.

## 외부 검색과 이후 자동 조회

KIPRIS와 WIPO PATENTSCOPE 공식 검색 링크를 제공합니다. 작성한 아이디어 설명·첨부파일을 외부 서비스에 자동 전송하지 않습니다. 아직 공개되지 않은 출원이나 다른 국가의 권리는 검색 결과에서 빠질 수 있습니다.

운영 설정은 `KIPRIS_PLUS_API_KEY` 등록 여부와 `KIPRIS_PLUS_PRODUCT_APPROVED=true` 신고 여부만 반환합니다. 인증키 자체는 서버 전용입니다. **키를 넣어도 현재 버전의 자동 조회는 켜지지 않습니다.** KIPRIS Plus 회원가입·서비스 신청·상품 승인/이용 조건 확인 후, 승인 상품의 실제 API 명세에 맞춰 번호 조회 어댑터·응답/오류·출처 시각·비용 한도·캐시/보존 기준을 별도 검증해야 합니다. 확인되지 않은 엔드포인트를 가정해 호출하지 않습니다.

향후에는 판매자가 제출한 번호로 공개 서지·법적 상태·권리자 정보를 조회하고 운영자의 대조를 돕는 방식이 적절합니다. 자동 유사도 점수로 법률 결론이나 가격을 확정하지 않습니다. 비공개 설명 전송이나 전문가 전달은 제공 범위를 명시한 별도 절차가 필요합니다.

## 저장·동시 변경·배포

- `idea_patents`: 등록 내용 버전, 신고·동의 버전, 운영 검토, 심사 revision/token/시각을 저장합니다. 판매자 수정 시 신고와 심사 대기 상태를 새 버전에 묶습니다.
- `order_patent_disclosures`: 주문 당시 공개 안내만 저장합니다. 거래 약관은 `2026-10-22-patent-draft-v2`로 갱신되며 기존 서약은 보존합니다.
- 심사와 결제는 DB 쓰기 시에도 신고·심사 버전을 확인합니다. 다른 운영자의 심사나 판매자 수정이 끼어들면 오래된 승인/구매를 막습니다. 신규 주문이 생성되지 않으면 권한·수수료·안내 기록도 생성하지 않습니다.
- 새로운 두 테이블은 `server/operations.sql`과 `db/schema.ts`에 추가했습니다. 독립 SQLite 실행은 시작 시 비파괴 DDL을 적용합니다. 원격 D1에는 승인된 대상과 백업을 확인한 뒤 마이그레이션 생성·적용이 필요합니다. 원격 DB 변경은 수행하지 않았습니다.
- 공식 자료 링크는 허용된 HTTPS 호스트만 받으며 로그인 정보·인증키/토큰 쿼리·fragment를 차단합니다. 운영자가 번호와 실제 자료가 맞는지 확인해야 합니다.

## 검증 근거

`npm test`의 특허 통합 검사는 필수 신고, 비대상 사유, 번호 형식, 권리관계, 공식 링크/확인일, 공개 승인 게이트, 운영 전용 자료 격리, 구매 안내 버전, 주문 고정 기록, 거래 직전 변경, 동시 심사/판매자 수정, 기존 글/주문, 키 비노출을 실제 Request→API→SQLite로 확인합니다. 기존 8개 검사 묶음과 QA 도구 검사도 유지합니다.

실제 브라우저 러너의 기존 17단계에는 미입력 오류, 신고 입력·임시 복원·수정, 권리 검토 없는 승인 거부, 운영 검토 입력, 구매 전 고지·원문 격리, 거래 기록의 특허 안내를 추가했습니다. 새 버전은 Actions 39748164227에서 전체 17단계 통과했으며 결과·증거·한계는 `QA_PATENT_V5_3.md`와 `VALIDATION.md`에 기록했습니다. 이전 v5.2.0 성공을 이번 기능의 검증으로 간주하지 않습니다.
