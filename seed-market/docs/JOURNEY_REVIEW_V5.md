# 판매자·구매자 전체 흐름 점검과 v5 개선

2026-10-20 · seed v5

판매자의 가입·등록·심사·수정·거래·정산·문의와 구매자의 탐색·가입·열람·독점 구매·권한 변경·환불을 연결해 재현했습니다. 단계를 따로 호출하는 데서 끝내지 않고 같은 아이디어·주문·이미지·수수료 원장을 끝까지 추적했습니다.

검증은 실제 Web Request → 공통 API → SQLite → 응답을 사용합니다. 이미지 저장소는 테스트용 메모리 어댑터입니다. 현재 환경의 서버 포트와 Chromium 실행 제한 때문에 실제 브라우저 클릭, OAuth, PG, R2·D1 배포를 검증한 결과는 아닙니다.

## 발견하고 반영한 항목

| 이용 중 문제 | v5 반영 |
| --- | --- |
| 반려된 글을 고칠 수 없어 내용을 다시 작성해야 함 | 내 아이디어·상세에서 수정과 재검토 진입. 본문·분류·가격·이미지를 불러오고 기존 이미지를 유지하거나 교체 |
| 두 창에서 수정하거나 심사 도중 내용이 바뀌면 서로 덮어쓸 수 있음 | 등록 버전 비교와 트랜잭션으로 한 번만 반영. 운영 승인에도 확인한 버전 요구 |
| 수정 기능으로 이미 판매된 자료를 바꿀 위험 | 결제 이력이 전혀 없는 검토 대기·반려 글만 수정. 공개·게시 중단·판매완료·환불 이력 글은 수정 차단 |
| 수정 시 새 수수료가 과거 등록 조건에 적용될 위험 | 처음 합의한 수수료·정산 대기 유지, 수정 화면에도 같은 조건 표시 |
| 등록 응답이 끊기면 성공 여부가 불분명함 | 요청 번호·입력 해시·접수 결과를 본문과 같은 트랜잭션에 저장. 내 요청 결과 조회와 재시도, 같은 번호의 다른 내용 차단 |

| 가입을 마치면 원래 보던 구매·찜·등록 작업을 잃음 | 인증 후 역할에 맞는 원래 작업으로 이어가기. 역할 기본 선택 유지, 만료·역할 불일치 검사 |
| 구매가 성공했어도 목록 갱신 오류를 결제 실패로 오해할 수 있음 | 성공 응답 이후 목록 갱신 실패를 분리. 구매 완료 화면에서 상세 자료·거래 기록으로 이동 |
| 결제창을 닫았다 열면 재시도 번호가 바뀜 | 계정·아이디어·권리별 요청 번호를 세션에 유지. 다시 동의한 요청도 같은 번호로 결과 확인 |
| 내 열람 목록에서 판매완료·게시 중단과 열람 가능을 구분하기 어려움 | 현재 권한을 별도 표시. 접근 종료·보류된 항목은 거래 기록으로 연결해 막힌 상세 화면 반복 진입 감소 |
| 거래 기록에서 환불·현재 권한을 확인할 수 없음 | 구매 종류·가격·주문 번호·구매 시각·최초 열람·서약·환불 시각/사유·현재 권한과 문의 경로 제공 |
| 미사용 이미지가 쌓이면 업로드 한도에서 막힘 | 판매자 계정의 미사용 업로드 관리. 자신의 미사용 파일만 삭제, 등록 자료는 제외 |
| 이미지 삭제와 판매 등록이 겹치면 등록된 파일을 지울 수 있음 | DB에서 미사용 상태를 원자적으로 확인하고 삭제 확정한 뒤 저장소 정리. 등록이 먼저 완료되면 삭제 차단 |
| 저장소 삭제 실패 후 정리할 대상이 사라질 수 있음 | 삭제 작업을 DB에 남기고 성공할 때만 제거. 다음 미사용 목록 조회·업로드에서 재시도 |
| API에서 태그·제공 자료가 조용히 잘림 | 개수·길이 초과를 명시적으로 거절해 입력과 판매 자료가 다르게 저장되는 문제 방지 |
| 요청 중 다른 화면으로 이동해 결과를 놓칠 수 있음 | 제출 중 이동 제어. 새 화면을 연 뒤 도착한 오래된 조회 응답은 반영하지 않음 |

## 판매자 재현 순서

| 순서 | 실행과 확인 |
| --- | --- |
| 1 | 판매자로 가입. 구매자 등록 요청은 서버에서 거절 |
| 2 | 종류·세부 유형·관련 분야, 요약·상세 기획·창작 근거, 두 가격, 공개·비공개 이미지를 준비해 검토 요청 |
| 3 | 같은 등록을 동시에 재시도해 아이디어 한 건만 생성. 응답을 받지 못한 상황에서 내 요청 번호로 접수 결과 조회 |
| 4 | 승인 전에는 검색·구매자 상세·공개 커버 접근이 차단됨을 확인 |
| 5 | 운영자가 반려. 판매자가 기존 글을 불러와 본문과 이미지를 수정하고 재검토 요청 |
| 6 | 플랫폼 기본 수수료를 바꾼 뒤에도 기존 글의 최초 수수료가 유지됨을 확인 |
| 7 | 동시 수정은 한 건만 성공. 이전 버전을 본 운영자의 승인은 거절하고 최신 버전으로 승인 |
| 8 | 공개 이후 수정·이미지 임의 삭제 차단. 미사용 이미지만 정리 |
| 9 | 구매자 열람·독점 구매 이후 수수료 원장 확인. 진행 중 문의가 있으면 정산 보류 |
| 10 | 판매자 답변 → 운영 환불 → 대기 기간 경과 → 순 정산 가능액 확인 → 중복 없는 정산 요청 → 테스트 정산 완료 |

## 구매자 재현 순서

| 순서 | 실행과 확인 |
| --- | --- |
| 1 | 종류별 검색·무료 요약·가격 확인, 찜. 비공개 본문과 이미지 식별자는 검색 결과에 없음 |
| 2 | 가입 전에 선택한 구매·찜 작업을 보관하고 역할 선택 후 이어가는 상태 처리 확인 |
| 3 | 열람권 없이 사용권 구매 시도는 서버에서 차단 |
| 4 | 비사용 서약과 버전에 동의하고 테스트 열람권 구매. 같은 요청 재시도는 같은 주문 반환 |
| 5 | 상세 본문·이미지 열람, 최초 접근 시각과 현재 열람 권한 확인 |
| 6 | 추가 독점 사용료와 열람료 포함 합계 확인 후 별도 동의·테스트 구매 |
| 7 | 구매자는 내 독점 사용권 표시. 다른 유료 열람자는 본문과 이미지 모두 차단되고 재열람 종료 안내 |
| 8 | 게시 중단 시 내 계정·거래 기록은 유지되며 상세 열람 보류 표시 |
| 9 | 접근이 막힌 상태에서도 내 주문에서 문의·환불 접수, 판매자 답변과 처리 결과 확인 |
| 10 | 테스트 환불 후 주문·서약·환불 사유 보존. 독점 사용권 환불도 자동 재판매·이전 열람권 복구로 이어지지 않음 |

가입 이어가기·세션 요청 번호는 순수 상태 모듈로 검증했습니다. 실제 공급자 화면 이동·브라우저 이벤트의 통합 확인은 남아 있습니다.

## 서버와 화면 연결

- 판매자: 작업실 → 이미지 API → 등록/수정 API → 자료·분류·정책·요청 기록·감사 로그 → 검토 대기 결과.
- 수정: `GET /api/ideas/:id/edit`, `POST /api/ideas/:id/revise`. 재검토는 `expectedVersion`과 `Idempotency-Key` 필요.
- 요청 복구: `GET /api/listing-requests/:key`. 본인 요청의 아이디어 ID·접수 버전·현재 심사 상태만 반환.
- 운영 승인: 기존 상태와 함께 `expectedVersion`을 필수로 검사. 분류 이전 샘플처럼 버전 자료가 없는 글은 0.
- 구매자: 결제 → 주문·서약·권한·수수료 원장 → 성공 화면 → 자료 또는 거래 기록.
- 거래 기록: `GET /api/orders/:id`는 본인 주문만 제공하며 현재 권한과 환불을 포함.
- 보관함: `GET /api/account`의 `access`는 구매한 아이디어의 현재 권한을 제공. 실제 상세·이미지 요청도 별도로 권한 재검사.
- 미사용 이미지: `GET /api/uploads`, `DELETE /api/uploads/:id`. 업로드와 등록 자료 삭제를 원자적으로 구분.

## 증거와 재실행

    npm run check
    npm test
    node scripts/design-preview.mjs /workspace/seed-market-v5-preview.html

- `tests/journeys.test.mjs`: 위 흐름, 동시 등록·수정, 쓰기 직전 이미지/심사 경쟁, 저장소 삭제 실패 재시도, 계정 격리, 입력 거절, 화면 상태·거래 템플릿 검사.
- 기존 거래·운영·검색·분류·화면 검증도 함께 통과.
- 실행 후 `.sites-runtime/journey-results.json`에 단계별 결과를 생성. 개인정보와 인증 키는 사용하지 않음.
- 정적 미리보기의 ‘구매 후 권한 화면’에서 열람 가능·재열람 종료·환불 기록을 선택 가능. 같은 API로 만든 가상 테스트 내역이며 실제 서비스·결제와 연결되지 않음.

## 운영 연결 전 남은 항목

실제 브라우저의 판매자·구매자 역할 전환과 가입 복귀, 모바일 파일 선택·키보드·초점, 네트워크 중단·세션 만료를 직접 확인해야 합니다. 현재 서버 재현 결과로 이 항목을 완료 처리하지 않았습니다.

실제 소셜 키·인증 메일, PG 승인/실패/환불·웹훅·사용권 예약, 판매자 본인확인·정산·세무, 최종 권리 계약은 연결 전입니다. Sites 소스 동기화 도우미와 설치된 빌드 의존성이 없어 배포하지 않았습니다. 배포 전에 `listing_requests`, `upload_cleanup`을 포함한 Drizzle 마이그레이션을 생성·검토하고 D1/R2에서 같은 경계 조건을 확인해야 합니다.

미사용 파일의 자동 보관 기간·정기 정리는 설정하지 않았습니다. 현재는 소유자의 명시적 삭제와 이후 조회·업로드 시 실패 작업 재시도를 제공합니다. 전체 이벤트 알림·대량 검색 인덱스·백업 복구는 별도 운영 작업입니다.
