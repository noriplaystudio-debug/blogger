첨부한 seed-market-v5.4.0-work-handoff.zip으로 한국어 아이디어 공유소 seed v5.4.0의 독립 QA를 진행해줘. PC에서 Work를 이용하고 있지만 네 실행 머신의 브라우저·서버 접근 가능 여부는 직접 확인해야 해. 설명·계획만 쓰지 말고 가능한 검사를 실제로 실행하고 결과 파일을 반환해줘.

목표와 역할
- 너는 검증 담당이야. 이 채팅에서는 앱 코드나 정책을 임의로 수정하지 말고, 오류·개선안·수정 가이드를 보고해줘. 실행에 필요한 일회성 QA 드라이버 설치와 격리 임시 데이터 생성은 허용돼.
- 배포, GitHub 커밋/PR/병합, Vercel/Sites 변경, 실제 결제·환불·송금·출원, 실제 소셜 계정/개인정보 입력, 외부 메시지 발송은 하지 마.
- 호스팅 ID는 QA_ONLY_NOT_A_SITE로 치환한 검증용 사본이므로 배포할 사이트를 찾거나 생성하지 마. API 키·환경변수의 실제 비밀값을 읽거나 보고서에 출력하지 마.

이번 사용자 결정 — 이 기준으로 검증해줘
1. 서비스는 일반인의 생각이 묻히지 않게 나누고 창업자·기업이 열람료로 구체적 설명·기획·방향을 살펴보는 아이디어 공유소야.
2. 특허는 참고 정보만 제공해. 미기재/미확인/유사 문헌 발견/전문가 상담 권장 상태 때문에 등록·일반 자료 승인·구매가 차단되면 오류야. 이전 v5.3의 특허 보완·전문가 상태 차단을 합격 기준으로 가져오지 마.
3. 출원 공개 문헌과 등록공보, 현재 유효한 권리를 구분해. 원문·공보 번호·제목·국가·문헌 확인일을 보여주되 현재 권리 존속·유효성·침해 여부는 미검증으로 안내해야 해. 데이터 없는 유사 특허나 검색 완료를 지어내지 마.
4. 목적과 보증 범위를 공지/판매/구매에서 알리되 전면 면책, 모든 거래 법적 효력 없음, 일괄 환불 불가로 안내하면 안 돼. 법정 책임과 이용자 권리는 보존해.
5. 추가 단독 이용권은 사이트 내 판매완료와 다른 구매자의 상세 재열람 종료 조건이야. 특허권·저작권·아이디어 자체의 법적 독점권을 자동 취득한다는 뜻이 아니야. 기존 두 단계 거래와 수수료·권한·환불·정산 기능은 검증해.
6. 특허 자동 검색 API, 실제 OAuth/PG/법률 의견은 미연결이야. 현재는 운영자가 공보를 참고 정보로 기록하는 방식이므로 자동으로 검증했다고 표시하지 마.

실행 순서
1. 새 작업 디렉터리에 안전하게 압축을 풀고 QA_METADATA.json, SOURCE_MANIFEST.json, seed-market/docs/WORK_QA_V5_4_PC.md, docs/IDEA_SHARING_PRINCIPLES.md, docs/VALIDATION.md를 읽어. manifest의 파일 해시와 package.json의 5.4.0 버전을 대조해. .env.local·DB·캐시·Git 인증·실제 사용자 자료가 포함되지 않았는지도 확인해.
2. Node.js 22.13 이상(24 권장)에서 seed-market 폴더의 npm run check, npm test, npm run qa:tools-test를 실행하고 각각 종료 코드와 요약을 남겨. 이 통과를 실제 UI 통과로 대체하지 마.
3. 현재 머신의 실행 가능한 Chrome/Chromium과 Playwright 1.62.1부터 확인해. 기존 브라우저가 있다면 정확한 경로를 SEED_BROWSER_EXECUTABLE에, 기존 고정 드라이버가 있다면 해당 index.mjs를 SEED_PLAYWRIGHT_PATH에 지정해. 경로·버전을 추측하거나 버전 검사를 무력화하지 마.
4. 브라우저는 있고 드라이버만 없다면 npm install --prefix tools/browser-qa --ignore-scripts --no-audit --no-fund --fetch-timeout=30000 --fetch-retries=1로 드라이버만 한 번 설치해. 앱 전체 npm install이나 Docker 빌드부터 시작하지 마. 브라우저가 없다면 npm run qa:prepare의 공식 준비를 한 번 시도할 수 있어. 같은 차단/손상 오류가 반복되면 설치 루프·실행 정책 우회를 중단하고 BLOCKED로 기록해.
5. npm run qa:doctor를 실행해. 실제 브라우저 실행, 같은 환경의 격리 서버, 홈 카드와 모바일 메뉴 확인이 모두 통과한 경우에만 npm run test:browser로 진행해. doctor 통과는 전체 거래 통과가 아니야. 호스트/루프백 보호를 풀거나 다른 머신의 localhost를 같은 서버로 가정하지 마.
6. 기본 러너 18단계 결과 JSON·스크린샷·trace를 확인하고, 가능한 지원 브라우저/컴퓨터 조작으로 PC 가독성·키보드 이동·긴 제목·모달 스크롤·닫기·돌아가기도 직접 점검해. 지원되는 실제 접속 수단이 없으면 이 추가 수동 검사는 NOT_RUN으로 남겨. 실물 모바일 테스트와 모바일 에뮬레이션을 구분해.

주요 확인 항목
- 비로그인에서도 상단 공지와 전문이 열리는지, 공유소의 목적과 법정 권리 보존 안내가 일관적인지.
- 판매자: 가입/복귀 → 소개/종류/이미지/상세 기획 → 선택 특허 입력 → 가격과 공지 확인 → 비공개 접수 → 보완/수정/일반 심사 승인. 특허 입력 없이도 진행 가능한지.
- 운영자: 참고 문헌 추가/수정/삭제, 국가·공보 번호·출원 공개/등록공보·원문 주소·확인일, 상담 권장 상태와 공개 승인이 독립적인지. 문헌/주소 불일치·키 포함 주소·미래 날짜는 기록 오류로 처리되는지. 거래 위험 판정과 입력 형식 검사를 구분해.
- 구매자 A/B: 요약 → 공지·가격 기준·특허 참고자료 → 동의/열람 결제 → 본문·이미지 → 추가 단독 이용 → 판매완료 및 다른 구매자 재열람 종료 → 거래 기록/문의. 상담 권장/참고 정보 미정리 상태에서도 거래 가능한지.
- 구매 당시 참고 문헌과 동의 문구 보존, 클라이언트가 보낸 가짜 보증/금액 무시, 비공개 운영 메모 격리, 정보 동시 수정 시 최신 안내 재확인 후 거래 가능한지.
- 중복 클릭/응답 유실 재시도/동시 구매, 문의/판매자 답변/환불/정산, 무료 나눔/이용 조건/금액 의견/통계, 모바일 메뉴·필터·가로 넘침.
- 판매 조건·결제 문구가 권리/수익 인증이나 무조건 면책으로 읽히지 않는지. 법률 문구의 개선 제안과 법률적 효력 확정을 구분해.

반환물 — 실제 실행일 Asia/Seoul 기준
A. seed-market-v5.4.0-qa-report-YYYY-MM-DD.md
B. seed-market-v5.4.0-qa-checklist-YYYY-MM-DD.json
C. 실패/개선 근거 스크린샷·관련 로그·가능하면 trace. 공유본에 DB·업로드 원본·쿠키·토큰·환경 비밀값은 포함하지 마.

보고서에는 검사한 버전/manifest/환경, 수행 명령·종료 코드, PASS/FAIL/BLOCKED/NOT_RUN, 실제 실행한 단계 수, 문제별 재현 순서·기대/실제·심각도·근거·추정 원인과 확신도·추천 수정 위치·재검증 기준을 적어줘. P0/P1 결함과 사용성 개선·환경 문제·재현되지 않은 제안을 분리해줘. 환경 차단을 제품 결함으로, 정적 템플릿이나 과거 GitHub 성공을 이번 Work의 브라우저 성공으로 기록하지 마.

최종 메시지에는 내가 원래 Codex 채팅에 첨부할 보고서 MD와 체크리스트 JSON의 다운로드 링크를 먼저 제공해줘. 무엇을 실제 확인했고 무엇을 확인하지 못했는지 짧게 설명하고, 구체적인 수정 가이드까지 보고서에 포함해줘.
